# 小电视提醒

独立 Android 电视应用，在所选哔哩哔哩客户端处于前台时累计本轮使用时长，并用遥控器可操作的悬浮窗提醒休息。每次电视关机或待机后清零，重新开机从 0 开始。

## 安装和首次使用

安装包：`dist/tv-bilibili-reminder-1.1.2-debug.apk`。这是使用本项目调试证书签名的可安装测试版，支持 Android 6.0 / API 23 及以上，无原生 CPU 架构限制。可覆盖安装旧版本，保留时间设置、客户端选择和开关状态。

1. 将 APK 复制到 U 盘，在电视文件管理器中打开安装；若电视有第三方应用安装开关，按电视提示开启。也可以在自行连接并授权电视 ADB 后运行：

   ```sh
   adb install -r dist/tv-bilibili-reminder-1.1.2-debug.apk
   ```

2. 在电视应用列表中打开 **小电视提醒**。
3. 在“计时客户端”中选择电视上实际使用的哔哩哔哩 / 云视听小电视。应用会尝试自动选择已安装的匹配客户端，也允许手动更改。
4. 点击“打开无障碍设置”，启用 **小电视提醒** 服务，再返回应用。页面应显示“提醒已就绪”。
5. 正常打开所选客户端，计时自动开始。

如果澎湃 OS 的无障碍入口被隐藏、服务无法启用或后台服务被系统限制，需要根据具体电视型号和固件检查。2026-11-08 在用户 REDMI 电视上确认了系统无障碍设置页面崩溃的问题和 ADB 启用服务的处理方式，见下文。部分 Android 版本对侧载应用启用无障碍时会要求先允许受限设置，应按设备实际提示操作。

无障碍服务只获取前台窗口所属包名来判断是否计时，不遍历视频界面、不读取账号或视频内容。应用没有网络权限，不上传数据。

## 设置和提醒规则

| APP 内设置 | 默认值 | 行为 |
| --- | --- | --- |
| 启用提醒 | 开启 | 关闭后立即撤下弹窗并暂停计时，保留本轮进度 |
| 开始提醒 | 13 分钟 | 到达后每个累计整分钟提醒，显示 5 秒倒计时后关闭 |
| 开始确认提醒 | 15 分钟 | 到达后每个累计整分钟提醒，需要遥控器选择【确认】 |

用遥控器方向键移动焦点，确定键操作。分钟数可用 `−` / `+` 按钮调整，也可在数字输入框中修改，最后点击“保存提醒时间”。确认提醒分钟数必须大于开始提醒分钟数，均为正整数。开关无需额外保存。

- 开关和分钟数只在 APP 设置页展示，提醒弹窗中没有这些设置。
- 默认满 13、14 分钟显示“时间快到了哦!”，5 秒后自动关闭；满 15、16、17……分钟显示“时间到了哦!”，默认聚焦【确认】。
- 从打开客户端进入前台开始计时，浏览、选片、暂停视频也计时。
- 退出客户端、切回桌面或进入本应用设置时暂停并撤下弹窗，重新进入客户端后继续本轮累计。
- **每次电视关机、遥控器待机或息屏时都清零**，不要求到达提醒时间，也不要求弹过提示。下次开机后从 0 开始；即使提醒开关已关闭，也会清零。按电视本地日期在次日同样清零。
- 确认弹窗显示期间继续累计。已有弹窗未关闭时跳过本次提醒，不叠加、不积攒。确认后等下一个累计整分钟。
- 本轮超过确认阈值后重新进入客户端，或重新打开开关再进入客户端，会立即显示一次确认提醒；如果电视已经关机/待机清零，则开始新一轮计时。
- 确认弹窗的返回键不会关闭它；主页键仍可离开客户端，离开后自动撤下弹窗。
- 修改阈值不会清空累计时间；若已经达到新的确认阈值，下次回到客户端时立即提醒。普通提醒不补发历史分钟。
- 设定会跨应用重启保存。累计进度每 5 秒及暂停等状态变化时提交保存，关机重置会同步落盘。Android 7.0 / API 24 及以上通过系统开机次数识别完整重启，正常返回客户端或服务自身重启不会清零。Android 6.0 或无法读取开机次数的固件依赖息屏/正常关机事件，错过这些事件时无法保证识别突然断电。服务未运行期间不补计。
- 待机清零需要无障碍服务收到息屏事件，或在电视非交互状态下运行过。如果服务被禁用或强制停止，整个待机、唤醒过程都未被它观察到，则无法事后识别该次待机；系统开机次数只能补偿完整重启，不能识别普通待机。
- 不主动暂停、退出或锁住哔哩哔哩。弹窗期间视频是否继续播放，取决于客户端对窗口焦点的处理。
- 本版本没有家长密码。能进入设置的使用者可以关闭提醒。

## 构建和测试

要求 Java 17 或兼容 JDK、Android SDK 35 与 Build Tools 35.0.0。项目固定使用 Gradle 8.11.1、AGP 8.9.2 和 Kotlin 2.1.20。

```sh
./scripts/android.sh :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

脚本优先使用已设置的 `JAVA_HOME` / `ANDROID_HOME`；本机还支持自动识别 IntelliJ 内置 JBR、默认 Android SDK，以及相邻 `family-location/.cache/android-sdk`。不会修改相邻项目。构建缓存、临时文件和调试签名都写入本项目 `.cache/`。

其他电脑可以显式指定工具路径：

```sh
JAVA_HOME=/path/to/jdk ANDROID_HOME=/path/to/android-sdk ./scripts/android.sh :app:assembleDebug
```

构建产物为 `app/build/outputs/apk/debug/app-debug.apk`。调试签名文件位于 `.cache/android-user/debug.keystore`，保留它才能让后续构建覆盖安装已有测试版；更换签名通常需要卸载旧版本，卸载会删除设置和累计记录。

- `core/`：纯 Kotlin 计时状态机，使用单调时间累计、开机次数识别完整重启、当地日期处理跨天。
- `app/`：设置页面、无障碍服务、前台识别、悬浮窗和本地存储。
- `core/build/reports/tests/test/`：计时测试报告。
- `app/build/reports/tests/testDebugUnitTest/`：Android / Robolectric 测试报告。
- `app/build/reports/lint-results-debug.html`：静态检查报告。

## 电视验收

### REDMI 真机排查记录（2026-11-08）

设备向 ADB 报告型号 `MiTV-MFTR0`、产品 `freeguy`、Android 14 / API 34；用户界面显示 REDMI TV / 澎湃 OS 3。实际客户端为 `com.xiaodianshi.tv.yst`（云视听小电视）。

“打开无障碍设置”跳转到 `com.android.tv.settings/.oemlink.AccessibilitySettingsActivity`，系统设置进程随后在 `AccessibilityFragment.onCreatePreferences` 中发生 `NullPointerException`，因此返回桌面。这是已由电视 crash 日志确认的设置页面故障，普通 APP 无法修复系统设置组件。

处理时通过已授权的 ADB 读取并备份系统的 `enabled_accessibility_services` 和 `accessibility_enabled`，在保留原有服务列表的前提下加入 `com.jk.tvreminder/com.jk.tvreminder.ReminderService` 并启用无障碍。随后 `dumpsys accessibility` 确认本服务已绑定、没有服务崩溃；累计时间开始增长。用户确认普通提醒出现并在倒计时结束后关闭，也确认“时间到了哦!”弹窗能通过遥控器【确认】关闭。系统窗口信息确认了确认提醒窗口获得焦点。返回本应用设置页后，两次间隔 5 秒读取的累计时间均为 240396 毫秒，确认退出目标客户端后暂停。此次没有验证电视重启、跨天和长期运行，也没有完成真机上保留弹窗跨整分钟的去重验收。

出现相同症状时，应先查看服务状态和崩溃日志，不要反复点击会崩溃的系统入口，也不要用固定命令覆盖电视已有的其他无障碍服务。启用服务后，日常开关仍使用本 APP 的“启用提醒”。

### 这台 REDMI 的待机清理限制与可选恢复组件

1.1.0 真机待机测试确认：累计由 359991 毫秒清零，系统处于 Asleep，唤醒后仍是 0；但固件随后执行 `PowerManagerService killAllThirdApp`，强制停止本应用，并把无障碍服务列表清空。唤醒后仅打开云视听小电视无法重新开始计时，需重新启用提醒服务。ADB 连接也可能在待机后关闭。

可选的 1.1.2 恢复组件针对这一问题，通过系统的通知监听绑定回调重新拉起进程，并恢复本应用的无障碍服务。需要两项**额外明确授权**，未授权时不会生效：

- 系统通知访问：用于系统重新绑定进程。代码没有读取、保存或上传通知内容；Android 12+ 的元数据声明禁用全部通知类型。系统授予的权限本身具有通知访问能力。
- `WRITE_SECURE_SETTINGS`：通过 ADB 授予，允许写系统安全设置。代码仅修改无障碍服务列表和总开关，保留其他服务；开启总开关也会使列表中原有服务生效；此权限在系统层面的范围比这两项设置更广。

撤销通知访问或上述安全设置权限后，自动恢复立即停止；APP 内“启用提醒”继续控制是否计时和显示提醒。只在两项授权都存在时运行恢复逻辑。1.1.2 已经用户同意在这台电视上授予两项权限。模拟固件强制停止 APP 后，真机检测到无障碍列表先被清空，约 1 秒后自动恢复绑定，进程重新启动且本轮进度保持；用户随后使用实体遥控器关机、开机，并进入云视听小电视后，确认本轮从零重新累计且显示“提醒已就绪”，完成本机端到端验收。该结果针对本机当前固件，不代表所有固件。

依据：本机 ADB 日志与 [同型号项目的实测记录](https://github.com/pengchujin/aerial-tv/blob/main/docs/devices/xiaomi-mitv-mftr0.md)，以及 [Android 通知监听服务文档](https://developer.android.com/reference/android/service/notification/NotificationListenerService)。实现未复制第三方应用代码，也不改变电视桌面或其他应用。

自动化测试不能替代 REDMI 固件和遥控器的实际验证。可以先将阈值改为 **1、2 分钟**，缩短验收时间：

1. 进入客户端，满 1 分钟检查普通提醒和 5 秒倒计时；期间遥控器应仍能操作客户端。
2. 满 2 分钟检查确认提醒，默认焦点在【确认】；返回键不关闭，确定键关闭。
3. 留着确认提醒超过一分钟，检查没有重复弹窗；确认后等下一个累计整分钟再提醒。
4. 按主页键离开，检查弹窗撤下、计时暂停；重新进入时继续累计，超时后立即提醒。
5. 在设置页关闭开关，再进入客户端，检查不计时、不提醒；重新开启后保留本轮进度。保持开关关闭并待机/唤醒，检查进度也会清零。
6. 未达到提醒时间、已经弹出提醒这两种情况下，分别让电视待机后唤醒，检查累计均从 0 开始；再检查完整重启后清零。同次开机仅重启 APP 服务应保留进度。
7. 验收后将阈值恢复为 **13、15 分钟**；如果本轮累计已超时，恢复后会正常按已超时处理。

真实跨午夜、异常断电恢复、权限开关和系统后台管理也应在设备上检查。系统设置入口和是否需要单独允许后台运行，以电视固件提供的功能为准。

构建验证（1.1.2）：74 项自动化测试通过，lint 无问题，APK 签名校验通过。Android 8.1+ 的通知授权使用 NotificationManager 官方查询接口，不依赖可能为空或过时的旧 secure 设置字段。
